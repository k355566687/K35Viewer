# 画像アーカイブ管理ビューア ユースケース定義書

**文書バージョン:** Ver.0.2  
**作成日:** 2026-11-06  
**対象:** MVP

## 1. 目的

本書は、画像アーカイブ管理ビューアのMVPでユーザーが行う操作と、アプリケーションが実行する処理をユースケース単位で定義する。

レビューでは、特に以下を確認する。

- 実際の整理作業の流れに合っているか
- 不要な確認や手順がないか
- ファイルを失う可能性がある処理に安全策があるか
- 10,000件以上のアーカイブを扱う際に不足する操作がないか
- MVPに不要な機能が混入していないか

## 2. アクター

| アクター | 説明 |
|---|---|
| ユーザー | ライブラリを登録し、画像アーカイブの閲覧・整理・ファイル管理を行う利用者 |
| ファイルシステム | ローカルドライブまたはネットワークドライブ上のフォルダとファイル |
| Windowsごみ箱 | 削除したアーカイブや更新前アーカイブの退避先。利用可能な保存先に限る |

## 3. 前提条件

- 対応OSはWindowsとする。
- MVPで扱うアーカイブ形式はZIPおよびCBZとする。
- MVPで扱う画像形式はJPEGおよびPNGとする。
- ライブラリ情報、フォルダ情報、アーカイブ情報および操作履歴はSQLiteへ保存する。
- サムネイルはローカルキャッシュへ保存する。
- 管理フォルダ配下は再帰的にスキャンする。
- アーカイブから離れる際の変更確認はMVPでは常に有効とする。
- ファイルを変更する処理の結果は、トースト表示するとともに操作履歴へ記録する。

## 5. ユースケース詳細

## UC-01 管理フォルダを登録する

### 目的

画像アーカイブを管理するフォルダをライブラリへ追加する。

### 事前条件

- ライブラリ画面が表示されている。

### 基本フロー

1. ユーザーが左ペインの「フォルダを追加」を選択する。
2. アプリケーションがフォルダ選択ダイアログを表示する。
3. ユーザーが対象フォルダを選択する。
4. アプリケーションが登録済みフォルダとの重複関係を確認する。
5. アプリケーションが管理フォルダをSQLiteへ登録する。
6. アプリケーションが「対象フォルダのスキャンを開始しました」とトースト表示する。
7. アプリケーションが対象フォルダ配下の初回スキャンをバックグラウンドで開始する。
8. スキャン完了時、登録件数および失敗件数をトースト表示する。
9. 最終結果を操作履歴へ記録する。

### 代替・異常フロー

- 選択フォルダが登録済みフォルダと同一の場合、追加せず登録済みであることを通知する。
- 選択フォルダが登録済みフォルダの配下にある場合、親フォルダの管理対象に含まれることを通知して追加しない。
- 選択フォルダが既存登録フォルダの親の場合、確認ダイアログで「配下の登録済みフォルダを、この親フォルダの配下へ統合します」と通知する。承認された場合、既存の子の登録フォルダは親の配下フォルダへ付け替え、Archive ID、サムネイル、最終閲覧位置、履歴を引き継ぐ。その後、親フォルダ全体を再スキャンする。
- フォルダへアクセスできない場合、登録せずエラーを通知する。

### 事後条件

- 登録成功時、フォルダが左ペインのツリーに表示される。

## UC-02 ライブラリをスキャンする

### 目的

登録フォルダと配下のサブフォルダから対応アーカイブを検出し、ライブラリへ登録する。

### 基本フロー

1. アプリケーションが「ライブラリのスキャンを開始しました」とトースト表示する。
2. アプリケーションが登録フォルダ配下を再帰的に列挙する。
3. ZIPおよびCBZを検出する。
4. 未登録アーカイブをSQLiteへ登録する。
5. フォルダ階層をSQLiteへ登録する。
6. 必要なアーカイブについて画像枚数と代表画像を取得する。
7. 代表画像からサムネイルを生成してキャッシュする。
8. 進行に応じてライブラリ画面へ登録結果を反映する。
9. 完了件数または失敗件数をトースト表示し、最終結果を履歴へ記録する。

### 代替・異常フロー

- アクセス不能フォルダはスキップし、失敗として記録する。
- 壊れたZIPはライブラリ上で識別可能な状態にし、処理を継続する。
- 対応画像が存在しないアーカイブはサムネイル未設定として登録する。
- スキャン中にユーザーがアーカイブ一覧を操作できるよう、処理はバックグラウンドで行う。

## UC-03 フォルダツリーで表示対象を絞り込む

### 目的

実フォルダ構造を利用して、中央領域に表示するアーカイブを絞り込む。

### 基本フロー

1. ユーザーが左ペインでフォルダを選択する。
2. アプリケーションが選択フォルダ自身と配下のサブフォルダを対象にSQLiteを検索する。
3. 該当するアーカイブを中央領域へ表示する。
4. 検索条件とソート条件が設定されている場合は、その条件も維持する。

### 補足

- 「すべて」は全登録フォルダを横断表示する。
- ツリーの展開・折りたたみは表示対象の絞り込みとは独立して扱う。

## UC-04 アーカイブを検索・ソートする

### 目的

10,000件以上のライブラリから目的のアーカイブを見つける。

### 基本フロー

1. ユーザーがファイル名検索欄へ文字列を入力する。
2. アプリケーションが現在選択中のフォルダ範囲内で部分一致検索する。
3. ユーザーがソート項目を選択する。
4. アプリケーションがファイル名、更新日時、ファイルサイズまたは画像枚数で並べ替える。

### 補足

- 検索およびソートはSQLite上で行う。
- 一覧項目は仮想化し、全件のUI要素を同時生成しない。

## UC-05 アーカイブを開く

### 目的

選択したアーカイブ内の画像を閲覧可能にする。

### 基本フロー

1. ユーザーがアーカイブをダブルクリックするか「開く」を実行する。
2. アプリケーションが対象ファイルの存在とアクセス可否を確認する。
3. アプリケーションがZIP内のJPEGおよびPNGエントリを列挙する。
4. アプリケーションが画像エントリを自然順で並べる。
5. 前回閲覧位置が有効な場合はその位置、無効な場合は先頭画像を表示する。
6. ビューア画面を1枚表示モードで開く。

### 代替・異常フロー

- ファイルが存在しない場合、ライブラリ再スキャンを促して開かない。
- ZIPが壊れている場合、エラーを通知してライブラリへ戻る。
- 対応画像が存在しない場合、その旨を通知する。
- 暗号化ZIPはMVP対象外として開けない旨を通知する。

## UC-06 1枚表示で画像を閲覧する

### 目的

アーカイブ内の画像を1枚ずつ確認する。

### 基本フロー

1. アプリケーションが現在画像を表示する。
2. ユーザーが左右キー等で前後画像へ移動する。
3. ユーザーが拡大、縮小、フィット、原寸または全画面を操作する。
4. アプリケーションが現在位置と最終閲覧位置を更新する。

### 補足

- 前後数枚のみ先読みし、全画像を同時展開しない。
- 削除予約済み画像は通常の前後移動対象から除外する。

## UC-07 一覧表示で画像を閲覧する

### 目的

アーカイブ内の画像全体をサムネイルで確認し、目的画像へ直接移動する。

### 基本フロー

1. ユーザーが一覧表示へ切り替える。
2. アプリケーションが現在画像を選択状態にしてサムネイルグリッドを表示する。
3. ユーザーが任意の画像を選択する。
4. ユーザーが画像をダブルクリックする。
5. アプリケーションが選択画像を起点に1枚表示へ切り替える。

### 補足

- サムネイルは遅延生成・遅延表示する。
- 削除予約済み画像は、削除予定であることを視覚的に識別できるようにする。

## UC-08 1枚の画像を削除予約する

### 目的

1枚表示中の不要画像を、アーカイブ更新時の削除対象にする。

### 基本フロー

1. ユーザーがDeleteキーを押す。
2. アプリケーションが現在画像を削除予約へ追加する。
3. アプリケーションが次の未削除画像を表示する。
4. 削除予定件数を更新する。

### 事後条件

- ZIP本体はまだ変更されない。

## UC-09 複数画像をまとめて削除予約する

### 目的

一覧表示で複数の不要画像をまとめて削除対象にする。

### 基本フロー

1. ユーザーがCtrlキーまたはShiftキーを使用して複数画像を選択する。
2. ユーザーがDeleteキーを押す。
3. アプリケーションが選択画像を削除予約へ追加する。
4. アプリケーションが各画像の削除予約状態を表示する。
5. 削除予定件数を更新する。

### 事後条件

- ZIP本体はまだ変更されない。

## UC-10 削除予約を取り消す

### 目的

アーカイブ更新前に、誤って指定した削除予約を解除する。

### 基本フロー

1. ユーザーが削除予約済み画像を選択する。
2. ユーザーが削除予約の解除操作を実行する。
3. アプリケーションが対象画像を削除予約から除外する。
4. 対象画像を通常の閲覧対象へ戻す。
5. 削除予定件数を更新する。

### 解除操作

- 一覧表示で削除予約済み画像を選択し、Deleteキーを押すと解除する（Deleteのトグル）。
- 削除予約済み画像の右クリックメニュー「削除予約を解除」でも解除できる。

## UC-11 アーカイブを離れて変更を確定する

### 目的

削除予約を1回の再構築でZIPへ安全に反映する。

### 起動条件

未確定の削除予約が存在する状態で、次のいずれかを実行する。

- ライブラリへ戻る
- 別アーカイブを開く
- アプリケーションを終了する

### 基本フロー

1. アプリケーションが変更確認ダイアログを表示する。
2. ユーザーが「更新する」を選択する。
3. アプリケーションが「対象アーカイブの更新を開始しました」とトースト表示する。
4. アプリケーションが元ZIPのサイズ、更新日時および存在を再確認する。
5. アプリケーションが同一保存先に一時ZIPを作成する。
6. 削除予約されていないエントリを一時ZIPへコピーする。
7. 一時ZIPを再オープンし、読み取り可能であることを確認する。
8. 元ZIPをWindowsのごみ箱へ移動する。
9. 一時ZIPを元のファイル名へ変更する。
10. SQLiteのサイズ、更新日時、画像枚数、サムネイルおよび最終閲覧位置を更新する。
11. 操作結果をSQLiteの履歴へ記録する。
12. 「対象アーカイブを更新しました。N枚の画像を削除しました」とトースト表示する。
13. 要求された遷移または終了を継続する。

### 代替フロー

#### A. 変更を破棄

1. ユーザーが「変更を破棄」を選択する。
2. アプリケーションが削除予約を破棄する。
3. ZIP本体を変更せずに離脱する。

#### B. キャンセル

1. ユーザーが「キャンセル」を選択する。
2. アプリケーションが離脱を中止する。
3. ビューアへ戻る。

### 異常フロー

- 元ZIPが外部で変更されていた場合、更新を中止し、再読み込みまたは変更破棄を促す。
- ディスク空き容量が不足している場合、一時ZIP作成前または作成中に中止し、元ZIPを保持する。
- 一時ZIP作成または検証に失敗した場合、一時ファイルを削除し、元ZIPを保持する。
- 元ZIPをごみ箱へ移動できない場合、破壊的な置換を行わず処理を中止する。ただし、ネットワークドライブの代替退避方式は別途設計する。
- 一時ZIPのリネームに失敗した場合、復旧可能な情報を履歴へ記録し、エラーを通知する。
- 失敗時には削除予約を保持し、ユーザーが再試行または破棄を選べるようにする。

### 排他制御

- 更新処理中は同一アーカイブへの重複操作を禁止する。
- 更新処理中にアプリケーションを終了しようとした場合、処理完了まで終了を保留する。

## UC-12 アーカイブ名を変更する

### 基本フロー

1. ユーザーがアーカイブを選択して名前変更を実行する。
2. アプリケーションが新しい名前を受け付ける。
3. 同名ファイルや禁止文字を確認する。
4. 実ファイル名を変更する。
5. Archive IDを維持したままSQLiteのパスとファイル名を更新する。
6. 履歴記録とトースト表示を行う。

### 異常フロー

- 同名ファイルが存在する場合は変更しない。
- ファイルが使用中またはアクセス不能の場合は変更しない。

## UC-13 アーカイブを移動する

### 基本フロー

1. ユーザーがアーカイブを選択して移動を実行する。
2. ユーザーが移動先フォルダを選択する。
3. アプリケーションが移動先のアクセス可否と同名ファイルを確認する。
4. 実ファイルを移動する。
5. Archive IDを維持したままSQLiteのパスを更新する。
6. フォルダツリーと一覧を更新する。
7. 履歴記録とトースト表示を行う。

### 異常フロー

- 移動に失敗した場合、SQLiteを更新しない。
- 異なるボリューム間ではコピー後に元ファイルを削除する処理となるため、コピー完了を検証してから元ファイルを処理する。

## UC-14 アーカイブを削除する

### 基本フロー

1. ユーザーがライブラリでアーカイブを選択して削除を実行する。
2. アプリケーションが削除確認ダイアログを表示する。
3. ユーザーが「削除」を選択する。
4. アプリケーションが対象をWindowsのごみ箱へ移動する。
5. SQLiteから対象を削除済みまたは不在として扱う。
6. 一覧から対象を除外する。
7. 履歴記録とトースト表示を行う。

### 異常フロー

- ごみ箱を利用できない保存先（ネットワークドライブ等）では、完全削除を自動実行しない。「ごみ箱へ移動できません。完全に削除しますか？ この操作は元に戻せません。」と確認し、ユーザーが「完全に削除」を選んだ場合のみ削除する。「キャンセル」を選んだ場合は、ファイルもSQLite上の登録も変更しない。
- 削除できない場合はSQLite上の登録を維持し、失敗を通知する。

## UC-15 アーカイブをエクスプローラーで表示する

### 基本フロー

1. ユーザーが対象アーカイブを選択する。
2. 「エクスプローラーで表示」を実行する。
3. アプリケーションがエクスプローラーを起動し、対象ファイルを選択状態で表示する。

### 異常フロー

- ファイルが存在しない場合はエクスプローラーを開かず、ライブラリ再スキャンを促す。

## UC-16 ライブラリを再スキャンする

### 目的

アプリ外で追加、削除、移動または変更されたファイルをライブラリへ反映する。

### 基本フロー

1. ユーザーが「再スキャン」を実行する。
2. アプリケーションが「ライブラリの再スキャンを開始しました」とトースト表示する。
3. アプリケーションが登録フォルダ配下をバックグラウンドで再帰走査する。
4. Path、Size、LastWriteTime等をSQLiteの記録と比較する。
5. 新規ファイルを登録する。
6. 変更ファイルのメタデータとサムネイルを更新する。
7. 不在ファイルをライブラリから除外する。
8. フォルダツリーを更新する。
9. 追加、変更、削除および失敗の件数をトースト表示し、最終結果を履歴へ記録する。

### 同一性の扱い

- アプリ内の移動・名前変更は同じArchive IDを維持する。
- アプリ外の変更は完全追跡を保証しない。
- 同名ファイルの移動可能性は考慮できるが、名前まで変更された場合は原則として新規登録する。

## UC-17 起動時にライブラリの更新を確認する

### 目的

アプリケーション起動時に登録フォルダの差分をバックグラウンドで確認し、ライブラリを最新の状態へ更新する。

### 事前条件

- 1件以上の管理フォルダが登録されている。

### 基本フロー

1. アプリケーションがライブラリ画面を表示する。
2. アプリケーションが「ライブラリの更新を確認しています」とトースト表示する。
3. アプリケーションが登録フォルダ配下の差分チェックをバックグラウンドで開始する。
4. ユーザーは更新チェック中もライブラリを閲覧・操作できる。
5. アプリケーションがPath、Size、LastWriteTime等をSQLiteの記録と比較する。
6. 新規、変更および不在のアーカイブを検出する。
7. 差分がある項目だけ、メタデータ、画像枚数およびサムネイルを更新する。
8. フォルダツリーとアーカイブ一覧へ結果を反映する。
9. 変更がある場合、「ライブラリを更新しました。追加N件、変更N件、削除N件」とトースト表示する。
10. 変更がない場合、「ライブラリは最新です」とトースト表示する。
11. 最終結果を操作履歴へ記録する。

### 代替・異常フロー

- 管理フォルダが未登録の場合、更新チェックを実行せず、フォルダ追加を案内する。
- アクセス不能なフォルダはスキップし、アクセスできなかった件数を完了トーストと履歴へ記録する。
- ネットワークドライブが未接続の場合、その配下の登録を即時削除せず、一時的なアクセス不能として扱う。
- 更新チェック中にスキャン対象のファイルが変化した場合、当該ファイルを失敗または再確認対象として扱い、他の処理は継続する。

### 性能要件

- 起動時に全ZIPの内部を再解析しない。
- Path、Size、LastWriteTime等による差分確認を基本とする。
- 差分が検出されたアーカイブのみ内部情報とサムネイルを再取得する。
- ライブラリ画面の表示を更新チェック完了まで待たせない。

## UC-18 管理フォルダを管理対象から外す

### 目的

登録済みの管理フォルダをライブラリの管理対象から外す。実ファイルは変更しない。

### 事前条件

- ライブラリ画面の左ペインに管理フォルダが表示されている。

### 基本フロー

1. ユーザーが左ペインで管理フォルダ（登録フォルダ）を選択し、「管理対象から外す」を実行する。
2. アプリケーションが確認ダイアログ（DLG-03）を表示する。配下のアーカイブ件数を含める。
3. ユーザーが「外す」を選択する。
4. アプリケーションが管理フォルダと、配下のフォルダ・アーカイブ・サムネイル管理情報をSQLiteから削除する。
5. サムネイルキャッシュのファイル実体を削除する。
6. 一覧とフォルダツリーを更新する。
7. 履歴記録とトースト表示を行う。

### 補足

- 管理対象から外せるのは登録フォルダのみ。サブフォルダは親の配下として扱われるため、単独では外せない。
- アーカイブが存在していても外せる。ZIP / CBZ本体およびフォルダは削除しない。
- 閲覧位置、サムネイル等の記録は失われる。同じフォルダを再登録した場合は新規アーカイブとして扱う。
- 操作履歴は残る（`archive_id` はNULLになる）。

### 異常フロー

- スキャン中の場合は、スキャン完了またはキャンセル後に実行する。
- ビューアで開いているアーカイブが対象の場合は、ライブラリへ戻ってから実行する。

## 6. 共通処理方針

### 6.1 長時間処理の通知

スキャン、再スキャン、起動時更新チェックおよびZIP再構築など、完了まで時間を要する可能性がある処理は、開始時と終了時の両方でトースト通知する。

- 開始トーストは、ユーザー操作または自動処理を受け付けた直後に表示する。
- 完了トーストには、対象、結果および可能な場合は処理件数を含める。
- 失敗または一部失敗の場合は、元ファイルの状態とユーザーが次に取れる操作を示す。
- 開始通知は操作履歴へ記録せず、最終結果のみを記録する。
- バックグラウンド処理中も、安全に実行可能なライブラリ閲覧・検索等は継続できるようにする。

### 6.2 共通エラー処理

- ファイル変更に失敗した場合、SQLiteだけを先に更新しない。
- 元ファイルを保持できない可能性がある場合、処理を中止する。
- ユーザーが次に取れる操作をエラーメッセージへ含める。
- 失敗内容はトースト表示と操作履歴記録の両方へ反映する。
- 一時ファイルには元ファイルと衝突しない名称を使用する。
- アプリケーション異常終了後に残った一時ファイルの検出・整理方法は実装設計で定める。

## 7. レビュー時の主な確認事項

1. （確定）親フォルダ追加時は、既存の子登録を親の配下へ統合する。
2. ZIP内画像の並び順は自然順でよいか。
3. （確定）削除予約の解除はDeleteトグルと右クリックメニューとする。
4. 変更確定中に別アーカイブの閲覧を許可するか、完了まで待たせるか。
5. （確定）ごみ箱が使えない場合、アーカイブ削除は確認のうえ完全削除を許可する。ZIP再構築では元ZIPを退避できないため更新を中止し、元ZIPを保持する。
6. 壊れたZIPや画像なしZIPをライブラリ上でどのように表示するか。
7. 初回スキャン中にサムネイル生成をどの優先度で行うか。
8. 外部変更されたアーカイブの扱いが実際の運用に十分か。
9. 起動時更新チェック中に許可するファイル変更操作の範囲は適切か。
10. 「変更なし」の完了トーストを毎回表示するか。

## 8. MVP対象外

- RAR、7z等の追加アーカイブ形式
- 暗号化ZIP
- 見開き表示
- 操作履歴閲覧画面
- 設定画面
- タグ、評価、コメント
- 高度な同一性判定
- アプリ独自の更新後Undo
- 動画、PDF、単体画像等のライブラリ管理
