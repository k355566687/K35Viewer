# 画像アーカイブ管理ビューア 画面一覧

**文書バージョン:** Ver.0.2.1（4.5のキー割り当てを確定）  
**作成日:** 2026-11-06  
**対象:** MVPおよび将来拡張

## 1. 基本方針

MVPでは画面数を抑え、次の主要作業を最短の動線で実行できることを優先する。

```text
1万件以上のアーカイブから探す
  ↓
アーカイブを開く
  ↓
画像を閲覧・整理する
  ↓
変更を確定する
  ↓
ライブラリへ戻る
```

独立した主要画面は、以下の2画面とする。

- ライブラリ画面
- ビューア画面

設定画面および操作履歴画面は将来仕様とする。

## 2. 画面・UI一覧

| ID | 画面・UI | MVP | 主目的 |
|---|---|---:|---|
| SCR-01 | ライブラリ画面 | 対象 | 全アーカイブの検索・閲覧・ファイル管理 |
| SCR-02 | ビューア画面 | 対象 | アーカイブ内部画像の閲覧・削除予約 |
| DLG-01 | アーカイブ変更確認ダイアログ | 対象 | 未確定変更の更新・破棄・離脱中止 |
| DLG-02 | アーカイブ削除確認ダイアログ | 対象 | アーカイブ自体の削除確認 |
| DLG-03 | 管理フォルダ解除確認ダイアログ | 対象 | 管理フォルダを管理対象から外す確認 |
| UI-01 | トースト通知 | 対象 | 操作結果の一時通知 |
| SCR-03 | 設定画面 | 将来 | アプリケーション動作の設定 |
| SCR-04 | 操作履歴画面 | 将来 | 過去のファイル操作結果の確認 |

## 3. SCR-01 ライブラリ画面

### 3.1 目的

複数の登録フォルダに存在する画像アーカイブを横断表示し、目的のアーカイブを検索・選択・管理する。

ライブラリ画面を、アプリケーションのホーム画面兼ファイルマネージャとする。

### 3.2 上部領域

以下の機能を配置する。

- ファイル名検索
- 表示方式切替
  - サムネイル表示
  - 詳細表示
- ソート
  - ファイル名
  - 更新日時
  - ファイルサイズ
  - 画像枚数
- ライブラリの再スキャン

### 3.3 左ナビゲーション

登録フォルダとその配下のサブフォルダを、実際のフォルダ構造に沿ったツリー形式で表示する。

例：

```text
ライブラリ

すべて

▼ D:\Archive
   ├─ 漫画
   │  ├─ 2025
   │  └─ 2026
   ├─ 写真集
   └─ 資料

▼ E:\Books
   ├─ 整理済
   └─ 未整理

▸ \\NAS\Images

＋ フォルダを追加
```

- 管理対象フォルダのスキャンは再帰的に行う。
- 「すべて」は、すべての登録フォルダを横断表示する。
- 登録フォルダまたはサブフォルダを選択すると、そのフォルダ自身と配下の全サブフォルダにあるアーカイブを表示する。
- 親フォルダが登録済みの場合、その配下は管理対象に含まれるため重複登録しない。
- フォルダツリー情報はSQLiteへ保持し、通常表示時に毎回ファイルシステムを走査しない。
- 管理対象フォルダの追加は、設定画面ではなくライブラリ画面から実行する。

### 3.4 中央領域

アーカイブ一覧を表示する。

#### サムネイル表示

各アーカイブについて、最低限次の情報を表示する。

- 表紙サムネイル
- ファイル名
- 画像枚数

#### 詳細表示

各アーカイブについて、次の情報を列形式で表示する。

- ファイル名
- 保存場所
- 画像枚数
- ファイルサイズ
- 更新日時

### 3.5 アーカイブ操作

選択したアーカイブに対して次の操作を提供する。

- 開く
- 名前変更
- 別フォルダへの移動
- 削除
- エクスプローラーで表示

基本操作に加えて、右クリックメニューからも実行できる構成を想定する。

### 3.6 表示性能

10,000件以上のアーカイブを扱うため、次を前提とする。

- SQLiteのインデックスから一覧情報を取得する
- サムネイルキャッシュを利用する
- 一覧項目を仮想化する
- サムネイルを遅延読み込みする
- 一覧表示のたびにZIP本体を開かない

## 4. SCR-02 ビューア画面

### 4.1 目的

選択したアーカイブ内の画像を閲覧し、不要な画像を削除対象として予約する。

画像の閲覧領域を最大限確保し、常時表示するUI要素は必要最小限とする。

### 4.2 表示モード

ビューア画面は、同一アーカイブに対して次の2つの表示モードを提供する。

#### 4.2.1 1枚表示

画像を1枚ずつ大きく表示し、前後移動、拡大・縮小、フィット、原寸表示、全画面表示および現在画像の削除予約を行う。

最低限、次の情報を画面端に表示する。

```text
ABC.zip
42 / 186
削除予定 3枚
```

#### 4.2.2 一覧表示

アーカイブ内の画像を、ライブラリ画面と同様のサムネイルグリッドで一覧表示する。

各項目には最低限、次を表示する。

- 画像サムネイル
- アーカイブ内ファイル名
- 削除予約状態

一覧表示では、CtrlキーおよびShiftキーによる複数選択を可能とし、選択した複数画像をまとめて削除予約できる構造とする。

### 4.3 表示モード間の連携

1枚表示と一覧表示では、現在位置、選択状態および削除予約状態を共有する。

- 1枚表示から一覧表示へ切り替えた場合、閲覧していた画像を選択状態にする。
- 一覧表示で画像をダブルクリックした場合、その画像を起点として1枚表示へ切り替える。
- どちらの表示モードで行った削除予約も、共通の削除予定件数へ反映する。
- 表示モードを切り替えてもZIP本体への変更は確定しない。

### 4.4 基本操作

- 1枚表示と一覧表示の切替
- 前の画像へ移動
- 次の画像へ移動
- 拡大・縮小
- ウィンドウに合わせる
- 原寸表示
- 全画面表示
- 現在画像を削除予約
- 選択した複数画像を削除予約
- ライブラリ画面へ戻る

### 4.5 キーボード操作

MVPではキー割り当てを固定する。

| 操作 | キー |
|---|---|
| 前の画像 | 左矢印 |
| 次の画像 | 右矢印 |
| 現在画像または選択画像を削除予約 | Delete |
| 全画面切替 | F11 |
| ライブラリへ戻る | Esc |

Phase 5（1枚表示）の実装で、次のキー割り当てを確定した。

| 操作 | キー |
|---|---|
| 前の画像 | 左矢印、PageUp、Shift+Space |
| 次の画像 | 右矢印、PageDown、Space |
| 先頭の画像 / 末尾の画像 | Home / End |
| 拡大 / 縮小 | `+` / `-`（テンキーを含む）、Ctrl+マウスホイール |
| ウィンドウに合わせる | `0` |
| 原寸表示 | `1` |
| 前の画像 / 次の画像（マウス） | マウスホイールの上 / 下 |
| 拡大時の移動 | ドラッグ、スクロールバー |

- 上下の矢印キーは割り当てない（拡大時のスクロールに使う余地を残す）
- 1枚表示と一覧表示の切替のキー割り当ては、Phase 6（一覧表示）で確定する
- 全画面で Esc を押すと、全画面の解除だけではなく、ライブラリへ戻る（このとき全画面も解除される）。全画面だけを解除するには F11 を押す

### 4.6 削除予約

Delete操作時点ではZIPを書き換えず、現在画像または一覧で選択した複数画像を、削除予定としてセッション内に記録する。

削除予約後は、対象画像を通常の閲覧対象から除外する。1枚表示では次の画像を表示し、一覧表示では削除予約状態を視覚的に識別できるようにする。

アーカイブから離れるまでは、削除予約を取り消せる構造とする。

## 5. DLG-01 アーカイブ変更確認ダイアログ

### 5.1 表示条件

現在のアーカイブに未確定変更が存在し、次の操作が行われた場合に表示する。

- 別アーカイブを開く
- ライブラリ画面へ戻る
- アプリケーションを終了する

### 5.2 表示内容

例：

> ABC.zip で5枚の画像が削除対象になっています。  
> アーカイブを更新しますか？

### 5.3 選択肢

- **更新する**
  - 削除予約を反映してアーカイブを再構築する
  - 更新完了後に離脱する
- **変更を破棄**
  - 削除予約を破棄する
  - 元のアーカイブを変更せず離脱する
- **キャンセル**
  - 離脱を中止する
  - ビューア画面へ戻る

MVPでは変更確認を常に有効とする。

## 6. DLG-02 アーカイブ削除確認ダイアログ

### 6.1 表示条件

ライブラリ画面でアーカイブ自体の削除を実行した場合に表示する。

### 6.2 表示内容

例：

> ABC.zip を削除しますか？  
> ファイルはWindowsのごみ箱へ移動します。

### 6.3 選択肢

- **削除**
- **キャンセル**

MVPではアーカイブ削除確認を常に有効とする。

## 6.1 DLG-03 管理フォルダ解除確認ダイアログ

### 表示条件

ライブラリ画面の左ペインで、登録フォルダに対して「管理対象から外す」を実行した場合に表示する。サブフォルダには単独の解除操作を提供しない。

### 表示内容

例：

> D:\Archive を管理対象から外しますか？  
> 配下の 1,234 件のアーカイブがライブラリから消えます。  
> 閲覧位置などの記録も削除されます。  
> ファイル自体は削除されません。

### 選択肢

- **外す**
- **キャンセル**

## 7. UI-01 トースト通知

### 7.1 目的

ファイル操作の結果を、作業を妨げずにユーザーへ通知する。

### 7.2 表示例

- 5枚の画像を削除しました
- ABC.zip を移動しました
- ファイル名を変更しました
- ライブラリを更新しました
- アーカイブの更新に失敗しました

### 7.3 動作

- 画面右下などに表示する
- 数秒後に自動的に消去する
- 成功・警告・失敗を識別できる表示とする
- 同じ操作結果をSQLiteの操作履歴へ記録する

MVPでは操作結果のトースト表示と履歴保存を実装するが、履歴閲覧画面は実装しない。

## 8. SCR-03 設定画面

### 8.1 MVPでの扱い

設定画面はMVP対象外とする。

MVPでは次の設定値を固定する。

| 項目 | MVPの固定動作 |
|---|---|
| アーカイブ離脱時の変更確認 | 常にON |
| アーカイブ自体の削除確認 | 常にON |
| 更新前ZIP | 可能な場合はWindowsのごみ箱へ退避 |
| サムネイルキャッシュ保存場所 | アプリケーション側で自動決定 |
| キー割り当て | 固定 |
| ビューア表示設定 | 固定 |

登録フォルダの追加・管理は、ライブラリ画面で行う。

### 8.2 将来機能

将来の設定画面では、次の項目を設定可能とする。

- アーカイブ離脱時の確認 ON/OFF
- アーカイブ削除時の確認 ON/OFF
- 更新前ZIPの退避方法
- サムネイルキャッシュ保存場所
- キャッシュ削除
- キー割り当て
- ビューア表示方法

## 9. SCR-04 操作履歴画面

### 9.1 MVPでの扱い

操作履歴データはMVPからSQLiteへ保存するが、閲覧画面は将来仕様とする。

### 9.2 将来機能

通知一覧形式で、次の情報を時系列に表示する。

- 実行日時
- 操作種別
- 対象アーカイブ
- 操作内容
- 成功・失敗
- 削除画像数
- 移動元・移動先

## 10. 画面遷移

```text
アプリ起動
   ↓
SCR-01 ライブラリ画面
   ↓ アーカイブを開く
SCR-02 ビューア画面
   ↓ 戻る・別アーカイブ・終了
未確定変更なし ───────────────→ 離脱
   │
   └ 未確定変更あり
          ↓
      DLG-01 変更確認
          ├ 更新する → ZIP更新 → トースト → 離脱
          ├ 変更を破棄 → 離脱
          └ キャンセル → ビューアへ戻る
```

ビューアは別ウィンドウにせず、同じメインウィンドウ内でライブラリ画面と切り替える構成を基本案とする。

## 11. MVP画面構成の結論

MVPの主要画面は次の2つに限定する。

1. **ライブラリ画面**
   - 10,000件以上のアーカイブから探す
   - アーカイブ自体を管理する
2. **ビューア画面**
   - 1枚表示またはサムネイル一覧でアーカイブ内画像を見る
   - 単一または複数の不要画像を削除予約する

設定画面と操作履歴画面は将来実装とし、MVPでは安全側の固定動作を採用する。
