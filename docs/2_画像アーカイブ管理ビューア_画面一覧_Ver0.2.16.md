## 1. 基本方針

MVPでは画面数を抑え、次の主要作業を最短の動線で実行できることを優先する。

```text
1万件以上のアーカイブから探す
  ↓
アーカイブを開く
  ↓
画像を閲覧・整理する
  ↓
変更を確定する
  ↓
ライブラリへ戻る
```

独立した主要画面は、以下の2画面とする。

- ライブラリ画面
- ビューア画面

設定画面および操作履歴画面は将来仕様とする。

## 3. SCR-01 ライブラリ画面

### 3.1 目的

複数の登録フォルダに存在する画像アーカイブを横断表示し、目的のアーカイブを検索・選択・管理する。

ライブラリ画面を、アプリケーションのホーム画面兼ファイルマネージャとする。

### 3.2 上部領域

以下の機能を配置する。

- ファイル名検索
- 表示方式切替
  - サムネイル表示
  - 詳細表示
- ソート
  - ファイル名
  - 更新日時
  - ファイルサイズ
  - 画像枚数
- ライブラリの再スキャン

画面の見た目の確認（Ver.0.2.6）で、配置を次のとおり確定した。

- 一覧の上を2段にする。1段目に検索・並べ替え（降順）・表示方式の切替、2段目に選択中のアーカイブへの操作ボタン（3.5）を置き、「再スキャン」は2段目の右端に離して置く（操作ボタンと押し間違えないため）
- ウィンドウの幅が狭くても、ボタン・選択肢の文字が切れないようにする

### 3.3 左ナビゲーション

登録フォルダとその配下のサブフォルダを、実際のフォルダ構造に沿ったツリー形式で表示する。

例：

```text
ライブラリ

すべて

▼ Archive            （D:\Archive）
   ├─ 漫画
   │  ├─ 2025
   │  └─ 2026
   ├─ 写真集
   └─ 資料

▼ Books              （E:\Books）
   ├─ 整理済
   └─ 未整理

▸ Images(接続なし)   （\\NAS\Images）

＋ フォルダを追加
```

括弧内は、ツールチップで表示するフルパス（画面のツリーには表示しない）。

- 管理対象フォルダのスキャンは再帰的に行う。
- 「すべて」は、すべての登録フォルダを横断表示する。
- 登録フォルダまたはサブフォルダを選択すると、そのフォルダ自身と配下の全サブフォルダにあるアーカイブを表示する。
- 親フォルダが登録済みの場合、その配下は管理対象に含まれるため重複登録しない。
- フォルダツリー情報はSQLiteへ保持し、通常表示時に毎回ファイルシステムを走査しない。
- 管理対象フォルダの追加は、設定画面ではなくライブラリ画面から実行する。

Phase 9 の実装で、管理フォルダを管理対象から外す操作（UC-18）を確定した。

- ツリーで管理フォルダ（最上位のフォルダ）を選び、左下の「管理対象から外す」ボタン、またはツリーの右クリックメニュー「管理対象から外す」で実行する。確認ダイアログ（DLG-03）を表示する
- 実行できるのは、管理フォルダ自身を選んでいるときだけ。「すべて」とサブフォルダでは、ボタンを無効にする（メニューは何もしない）
- スキャン中（起動時の更新チェックを含む）は実行できない。ビューアで開いているアーカイブは、ビューアの表示中はライブラリ画面を操作できないため、対象にならない
- 押せないときは、ボタンにマウスを載せると、その理由をツールチップで示す（「スキャンや操作の実行中は外せません。終わってから操作してください」「管理フォルダ（ツリーの最上位のフォルダ）を選ぶと外せます」）。押せるときは、「ファイルは削除されません」と示す
- 左下の3つのボタン（「＋ フォルダを追加」「管理対象から外す」「⚙ 設定」）は、ツリーの領域の幅いっぱいに表示し、文字は中央に置く

画面の見た目の確認（Ver.0.2.6）で、ツリーの表示を次のとおり確定した。

- 管理フォルダ（最上位）も、配下と同じくフォルダ名だけを表示する。フルパスはツールチップで表示する（左ペインの幅を取らないため）。ドライブ直下を登録した場合など、フォルダ名がないときはパス全体（`E:\` 等）を表示する
- 接続できない管理フォルダは、名前のあとに「(接続なし)」を付ける
- ツリーは横にスクロールしない。収まらない名前は、ツールチップで確認する

### 3.4 中央領域

アーカイブ一覧を表示する。

#### サムネイル表示

各アーカイブについて、最低限次の情報を表示する。

- 表紙サムネイル
- ファイル名
- 画像枚数

#### 詳細表示

各アーカイブについて、次の情報を列形式で表示する。

- ファイル名
- 保存場所
- 画像枚数
- ファイルサイズ
- 更新日時

画面の見た目の確認（Ver.0.2.6）で、一覧の表示を次のとおり確定した。

- **サムネイル表示の並べ方**（エクスプローラーと同じ）: カードの大きさは変えない。1行に入るだけのカードを並べ、余った幅はカードの間に均等に配る。ウィンドウを広げて、もう1枚入る幅になったら、1行の枚数を増やす（左寄せで右に余白を残すことはしない）
- **詳細表示の保存場所**: 管理フォルダの名前と、そこからのパスで表示する（例: `Archive\漫画\2025`。管理フォルダの直下なら `Archive`）。フルパスはツールチップで表示する
- **詳細表示の列の幅**: ファイル名の列が、一覧の残りの幅を使う。横スクロールは出さない。収まらない文字は末尾を「…」にし、全体はツールチップで表示する
- **詳細表示の行の高さ**: 1万件を見渡せるよう、テーマの既定より低くする

### 3.5 アーカイブ操作

選択したアーカイブに対して次の操作を提供する。

- 開く
- 名前変更
- 別フォルダへの移動
- 削除
- エクスプローラーで表示

基本操作に加えて、右クリックメニューからも実行できる構成を想定する。

Phase 9 の実装で、次のとおり確定した。

- **選択**: アーカイブは1件だけ選択する。詳細表示とサムネイル表示で、同じ選択を使う（表示を切り替えても選択は残る）。検索・並べ替えで一覧を取得し直しても、一覧に残っていれば選択を保つ。サムネイル表示では、選択したカードの背景を変え、「✓ 選択中」の文字を表示する（色だけに頼らない）
- **操作の場所**: 一覧の上に、選択中のアーカイブへの操作ボタン（開く / 名前変更 / 移動… / 削除 / エクスプローラーで表示）を置く。選択がないときは無効。同じ操作を、詳細表示の行・サムネイル表示のカードの右クリックメニューからも実行できる。右クリックした項目は、メニューを開く前に選択される
- **操作の後**: 名前変更・移動の後は、同じアーカイブを選択したままにする。削除した場合、または移動して表示中のフォルダから外れた場合は、次の（なければ前の）項目を選択する
- 操作の実行中は、重ねて操作できない（ボタンは無効になる）

| 操作 | キー・マウス |
|---|---|
| 開く | ダブルクリック、Enter |
| 名前変更 | F2 |
| 削除 | Delete |
| 選択（サムネイル表示） | クリック、矢印キー（上下は1行分）、PageUp / PageDown（3行分）、Home / End |
| 選択（詳細表示） | クリック、一覧の標準のキー操作（矢印キーなど） |
| メニュー | 右クリック |

- サムネイル表示で選択をキーで動かすと、その行まで一覧がスクロールする。クリックしたあとは、一覧がキー操作を受け付ける
- 修飾キー（Ctrl / Alt）付きのキーは、これらの操作に使わない

**名前変更（UC-12）**: 「名前の変更」ダイアログに現在の名前を表示し、拡張子を除いた部分を選択した状態で開く。拡張子（.zip / .cbz）を省略すると、元の拡張子を付ける。使えない文字（\ / : * ? " < > |）、末尾の「.」、Windowsの予約名（CON、NUL、COM1 等）、256文字以上の名前、同じフォルダにある別のファイルと同じ名前は、理由をダイアログ内に表示して「変更」を押せなくする。大文字小文字だけの変更はできる。Enter で確定、Esc でキャンセル

**移動（UC-13）**: フォルダの選択ダイアログで移動先を選ぶ。移動先は管理フォルダの中に限る（外を選ぶと、理由を通知して移動しない）。同じフォルダ、移動先に同名のファイルがある場合も移動しない（上書きしない）

**エクスプローラーで表示（UC-15）**: エクスプローラーを開き、ファイルを選択した状態で表示する。ファイルが見つからない場合は開かず、「再スキャンしてください」と通知する

### 3.6 表示性能

10,000件以上のアーカイブを扱うため、次を前提とする。

- SQLiteのインデックスから一覧情報を取得する
- サムネイルキャッシュを利用する
- 一覧項目を仮想化する
- サムネイルを遅延読み込みする
- 一覧表示のたびにZIP本体を開かない

## 4. SCR-02 ビューア画面

### 4.1 目的

選択したアーカイブ内の画像を閲覧し、不要な画像を削除対象として予約する。

画像の閲覧領域を最大限確保し、常時表示するUI要素は必要最小限とする。

### 4.2 表示モード

ビューア画面は、同一アーカイブに対して次の2つの表示モードを提供する。

#### 4.2.1 1枚表示

画像を1枚ずつ大きく表示し、前後移動、拡大・縮小、フィット、原寸表示、全画面表示および現在画像の削除予約を行う。

最低限、次の情報を画面端に表示する。

```text
ABC.zip
42 / 186
削除予定 3枚
```

#### 4.2.2 一覧表示

アーカイブ内の画像を、ライブラリ画面と同様のサムネイルグリッドで一覧表示する。

各項目には最低限、次を表示する。

- 画像サムネイル
- アーカイブ内ファイル名
- 削除予約状態

一覧表示では、CtrlキーおよびShiftキーによる複数選択を可能とし、選択した複数画像をまとめて削除予約できる構造とする。

カードの並べ方は、ライブラリ画面のサムネイル表示と同じ（3.4。カードの大きさは変えず、余った幅をカードの間に均等に配る）とする（Ver.0.2.6）。

### 4.3 表示モード間の連携

1枚表示と一覧表示では、現在位置、選択状態および削除予約状態を共有する。

- 1枚表示から一覧表示へ切り替えた場合、閲覧していた画像を選択状態にする。
- 一覧表示で画像をダブルクリックした場合、その画像を起点として1枚表示へ切り替える。
- どちらの表示モードで行った削除予約も、共通の削除予定件数へ反映する。
- 表示モードを切り替えてもZIP本体への変更は確定しない。

Phase 6（一覧表示）の実装で、次の規則を確定した。

- 現在位置は、1枚表示と一覧表示で同じ値を共有する。一覧で移動した位置が、1枚表示に切り替えたときの表示画像になる
- 1枚表示から一覧表示へ切り替えたとき、すでに現在の画像を含む複数選択があればそれを維持する。含まない場合は、現在の画像だけを選択状態にする
- 一覧表示から1枚表示へ切り替えても、選択状態は保つ
- 一覧表示のカードのサムネイルは、画面に表示された頁だけ生成する（全頁を一度に展開しない）。一覧の表示中は、画像本体を読み込まない

### 4.4 基本操作

- 1枚表示と一覧表示の切替
- 前の画像へ移動
- 次の画像へ移動
- 拡大・縮小
- ウィンドウに合わせる
- 原寸表示
- 全画面表示
- 現在画像を削除予約
- 選択した複数画像を削除予約
- ライブラリ画面へ戻る

### 4.5 キーボード操作

MVPではキー割り当てを固定する。

| 操作 | キー |
|---|---|
| 前の画像 | 左矢印 |
| 次の画像 | 右矢印 |
| 現在画像または選択画像を削除予約 | Delete |
| 全画面切替 | F11 |
| ライブラリへ戻る | Esc |

Phase 5（1枚表示）の実装で、次のキー割り当てを確定した。

| 操作 | キー |
|---|---|
| 前の画像 | 左矢印、PageUp、Shift+Space |
| 次の画像 | 右矢印、PageDown、Space |
| 先頭の画像 / 末尾の画像 | Home / End |
| 拡大 / 縮小 | `+` / `-`（テンキーを含む）、Ctrl+マウスホイール |
| ウィンドウに合わせる | `0` |
| 原寸表示 | `1` |
| 前の画像 / 次の画像（マウス） | マウスホイールの上 / 下 |
| 拡大時の移動 | ドラッグ、スクロールバー |

- 上下の矢印キーは、1枚表示では、前後のアーカイブへ移る操作に割り当てた（次の段落）。拡大時のスクロールは、今は、ドラッグとスクロールバーだけ。将来、拡大時に矢印キーでスクロールしたくなったら、スクロールできるときだけ ↑ / ↓ をスクロールに使い、アーカイブへ移る操作は Ctrl+↑ / ↓ に寄せる、などの整理が要る

ビューアで、一覧に戻らずに、前後のアーカイブへ移る操作（GitHub の Issue #13）を、次のとおり確定した。

| 操作 | キー |
|---|---|
| 前のアーカイブ / 次のアーカイブ（1枚表示） | ↑ / ↓ |
| 前のアーカイブ / 次のアーカイブ（一覧表示） | Ctrl+↑ / Ctrl+↓（一覧表示では、↑ / ↓ が画像の選択に使われているため） |

- **前後の基準**: ライブラリの一覧の並び。選んでいるフォルダ（サブフォルダを含む）、検索、並べ替えが反映された、今の一覧そのもの。「すべて」を選んでいれば、全フォルダを合わせた1本の並びで進む（たとえばファイル名順なら、フォルダをまたいで進む）。フォルダを選んでいれば、そのフォルダの一覧の中だけで進み、別のフォルダへは飛ばない
- **端**: 先頭・末尾では止まる（ぐるっと回らない）。「これより前（後）に、開けるアーカイブはありません」と通知する
- **開けないものは飛ばす**: 一覧の状態で、開けないと分かっているもの（破損、画像なし、暗号化）は、飛ばして、次の開けるものへ進む。ファイルがないなどは、開いてみないと分からないため、飛ばさない。開けなかった場合は、理由を通知して、ライブラリへ戻る（今のアーカイブは、すでに閉じているため）。このとき、開こうとしたアーカイブが、ライブラリで選ばれている
- **削除予約があるとき**: ライブラリへ戻るときと同じ確認（DLG-01）を表示する。「更新する」なら、ZIP を更新してから、次のアーカイブを開く。「変更を破棄」なら、破棄して開く。キャンセルなら、今のアーカイブに留まる。確認の設定をオフにしていれば、確認なしで更新して移る（8.3）
- 移ったあと、ライブラリでも、今のアーカイブが選ばれる。Esc で戻ってライブラリが表示されたときは、選ばれているアーカイブまで、一覧がスクロールする（詳細表示、サムネイル表示とも。一覧が長くても、今見ていたものの位置にいる）。移り先のアーカイブは、前回の閲覧位置から開く
- 移る操作は、ビューアでアーカイブを開いている間だけ働く。ライブラリを表示しているときは、何もしない

Phase 6（一覧表示）の実装で、表示方式の切替と一覧表示の操作を確定した。

| 操作 | キー・マウス |
|---|---|
| 1枚表示と一覧表示の切替 | `G`、ツールバーの切替ボタン |
| 画像を1枚選択 | クリック |
| 選択の追加・解除 | Ctrl+クリック、Space |
| 範囲選択 | Shift+クリック（起点は直前に通常クリックした画像）、Shift+矢印 |
| その画像から1枚表示 | ダブルクリック、Enter |
| 移動 | 左右の矢印（1枚）、上下の矢印（1行分）、PageUp / PageDown（3行分）、Home / End |
| 全選択 | Ctrl+A |

- 切替に Tab を使わないのは、Tab がフォーカス移動に使われているため
- 一覧表示では、拡大・縮小などのズーム系のキーは処理しない

Phase 7（削除予約）の実装で、削除予約の操作を確定した。

| 操作 | キー・マウス |
|---|---|
| 削除予約の追加・解除（トグル） | Delete（1枚表示・一覧表示のどちらでも） |
| 選択した画像を削除予約 / 削除予約を解除 | 一覧表示で画像を右クリック → 「削除予約」/「削除予約を解除」 |
- 全画面で Esc を押すと、全画面の解除だけではなく、ライブラリへ戻る（このとき全画面も解除される）。全画面だけを解除するには F11 を押す

### 4.6 削除予約

Delete操作時点ではZIPを書き換えず、現在画像または一覧で選択した複数画像を、削除予定としてセッション内に記録する。

削除予約後は、対象画像を通常の閲覧対象から除外する。1枚表示では次の画像を表示し、一覧表示では削除予約状態を視覚的に識別できるようにする。

アーカイブから離れるまでは、削除予約を取り消せる構造とする。

Phase 7（削除予約）の実装で、次の動作を確定した。

- **対象**: 1枚表示では現在の画像。一覧表示では選択中の画像（選択がなければ現在の画像）
- **トグル**: 対象がすべて予約済みなら解除し、そうでなければ（未予約が1枚でもあれば）全部を予約する
- **1枚表示で予約したとき**: 次の（なければ前の）予約されていない画像を表示する。移動先がない（すべて予約済みになった）場合は、最後の画像をその場に「削除予定」の表示で残す
- **移動の対象外**: 前後移動（矢印・PageUp/PageDown・Space・ホイール）と、先頭・末尾への移動（Home / End）は、削除予約された画像を飛ばす。ただし、一覧表示でのクリック・矢印キーなどによる位置指定は、予約済みの画像にも移動できる（解除するため）
- **予約済みの画像を1枚表示した場合**（一覧で予約済みの画像をダブルクリックしたとき）: 画像を薄く表示し、「削除予定（Deleteで解除）」の帯を出す。Delete で解除できる
- **表示**: 一覧表示では、予約済みの画像を薄く表示し、「削除予定」の文字を重ねる（色だけに頼らない）。削除予定件数（「削除予定 3枚」）は、画面右下の現在位置の表示に、1枚表示・一覧表示のどちらでも、全画面でも表示する
- 右クリックしたのが選択中の画像なら、複数選択を保ったままメニューを使う。選択外の画像なら、その1枚だけを選択してから開く
- 削除予約はセッション内にだけ保持する。ZIP本体、DB、操作履歴は変更しない

## 5. DLG-01 アーカイブ変更確認ダイアログ

### 5.1 表示条件

現在のアーカイブに未確定変更が存在し、次の操作が行われた場合に表示する。

- 別アーカイブを開く
- ライブラリ画面へ戻る
- アプリケーションを終了する

### 5.2 表示内容

例：

> ABC.zip で5枚の画像が削除対象になっています。  
> アーカイブを更新しますか？

### 5.3 選択肢

- **更新する**
  - 削除予約を反映してアーカイブを再構築する
  - 更新完了後に離脱する
- **変更を破棄**
  - 削除予約を破棄する
  - 元のアーカイブを変更せず離脱する
- **キャンセル**
  - 離脱を中止する
  - ビューア画面へ戻る

MVPでは変更確認を常に有効とする。

Phase 7（削除予約）の実装で、次の動作を確定した。

- 表示するのは、削除予約が1枚以上あり、ビューアからライブラリへ戻る（Esc、戻るボタン）とき、またはウィンドウを閉じる（アプリを終了する）とき。削除予約がなければ表示しない。ビューアを開いたまま別のアーカイブを開く操作（↑ / ↓ で前後のアーカイブへ移る）も、ライブラリへ戻る操作と同じく、削除予約があれば確認する
- 「キャンセル」が既定のボタン（Enter）で、Esc でもキャンセルになる。ダイアログを何も選ばずに閉じた場合もキャンセル
- 「変更を破棄」を選ぶと、削除予約を破棄してZIP本体を変更せずに離れる。アプリを終了する場合も同じ
- 「更新する」は、更新できないときは選べない（ボタンは無効で、理由を本文に表示する）。更新できないのは次の場合
  - ファイルが、ビューアで開いた時点から外部で変更されている（サイズまたは更新日時が異なる）、またはファイルがなくなっている
  - 元のファイルをWindowsのごみ箱へ退避できない保存先（ネットワークドライブ・UNCパス、リムーバブルドライブ、ごみ箱を使わない設定のドライブ、ごみ箱の最大サイズを超えるファイル）。この場合に自動で完全削除へ切り替えることはない。「変更を破棄」でのみ離れられる

Phase 8（ZIP再構築）の実装で、「更新する」を選んだときの動作を確定した。

- **更新中の表示**: 画面全体を覆う表示に「アーカイブを更新しています」と進行状況（確認中 / 作成中 / 確認中 / 置き換え中 / 記録中）を表示する。この間、画面の操作とキー入力は受け付けない
- **キャンセル**: 「キャンセル」ボタンまたは Esc で、更新を中止できる。中止できるのは、新しいアーカイブの作成と確認まで。元のアーカイブをごみ箱へ移す処理を始めたあと（「置き換え中」以降）は、中止できず、最後まで完了する。中止した場合は、元のアーカイブと削除予約が残り、ビューアに留まる
- **成功したとき**: 「「ABC.zip」を更新しました。N枚の画像を削除しました」を通知し、ライブラリ画面へ戻る（アプリの終了時は、更新が終わってから終了する）。ライブラリ画面では、画像枚数とサムネイルが更新後の内容に作り直される。更新後に開き直したときは、更新前に見ていた画像（削除された画像だった場合は、次の画像）から開く
- **失敗したとき**: 理由を通知し、ビューアに留まる。元のアーカイブは変更されず、削除予約も残る。もう一度 Esc で戻ろうとすると変更確認が表示され、再び「更新する」を選ぶか、「変更を破棄」で離れられる
- **置き換えの途中で失敗した場合**（まれ）: 更新前のファイルはごみ箱にあり、更新後のファイルは一時ファイル（アーカイブと同じフォルダの `〜.k35tmp`）に残る。その場所を通知し、操作履歴にも記録する。この場合はビューアを閉じる
- **更新中の終了操作**: ウィンドウを閉じようとしても、更新が終わるまで閉じない。更新が終わってから閉じる
- **外部変更の通知**: ビューアでアーカイブを開いている間にウィンドウが前面に戻ったとき、そのアーカイブが外部で変更されていれば、「表示内容が古い可能性があります」と1回だけ通知する

**各項目の動作**

| バックアップを作成 | `backups` フォルダにバックアップのファイル（`K35Viewer-backup-〈日時〉.zip`）を作り、「バックアップを作成しました（ファイル名）」と通知する。作っている間は押せない。作ったあとは、「最後のバックアップ」の表示を更新する（Phase 13 で確定。「（手動）」「（自動）」を添える。なければ「まだありません」） |
| 自動バックアップを残す数 | 1〜20から選ぶ（既定は5）。選ぶと、その場で保存し、古い自動バックアップをすぐに整理する。手動で作ったものは、数に関わらず削除しない |

| 更新を確認 | GitHub のリリース（試用版を含む）を確かめる。ボタンを押したときだけ通信する。確認中は「確認しています…」（「中止」を押せる）。結果は、ボタンの下に「新しい版 vX.Y.Z があります」「最新の版です」「確認できませんでした（理由。接続できない、GitHub への問い合わせが多すぎる、など）」のように表示する。新しい版に、アプリの中で更新するためのファイル（配布物とハッシュ）がない場合は、「アプリの中では更新できません。「変更点を見る」から、手で入れ替えてください」と添え、「更新する」は押せない |
| 変更点を見る | ブラウザで、そのリリースのページ（GitHub）を開く。新しい版が見つかっているときだけ押せる |
| 更新する | 新しい版が見つかっていて、アプリの中で更新できるときだけ押せる。確認（「vX.Y.Z に更新しますか？」「アプリのデータをバックアップしてから、ダウンロードして、アプリを再起動して入れ替えます」。ボタンは「更新」/「キャンセル」、既定はキャンセル）のうえ、ダウンロード（進行を表示。「中止」を押せる）→ ハッシュ（SHA-256）の確認 → 展開 → アプリのデータの自動バックアップ → アプリを終了して入れ替え、新しい版を起動する。ダウンロードしてから確かめたあとにバックアップするのは、ダウンロードに失敗したときに、使わないバックアップを増やさないため。ハッシュが合わない、ダウンロードできない、アプリのフォルダに書き込めない（`C:\Program Files` の中など）場合は、何も入れ替えず、理由を表示し、「変更点を見る」から手で入れ替えられることを案内する。入れ替えに失敗した場合は、元の版に戻して起動し、理由を通知する。入れ替えられたら、「35Viewer を vX.Y.Z に更新しました」と通知する。**更新の間の表示**: 「更新する」の確認のあと、ダウンロードから新しい版を起動するまでの間は、設定画面の上に、画面全体を覆う「アプリを更新しています」の表示を出す。今していること（ダウンロードした量、ハッシュの確認、展開、バックアップ、新しい版の起動）と、進みの棒（ダウンロードの間は割合、ほかは動き続ける表示）を出し、押せるのは「中止」だけ。ほかの項目は、マウスでもキーボードでも操作できず、設定画面も閉じられない。新しい版を起動する段階に入ったら、中止もできない。失敗・中止すれば、表示は消えて、元の設定画面に戻る。入れ替えの間（古いアプリが終わってから、新しい版の画面が出るまで）は、小さな「35Viewer を vX.Y.Z に更新しています」のウィンドウを出す（操作も、閉じることもできない）。新しい版の画面が出ると、自動で消える |

```text
          ├ 変更を破棄 → 離脱
          └ キャンセル → ビューアへ戻る
```

ビューアは別ウィンドウにせず、同じメインウィンドウ内でライブラリ画面と切り替える構成を基本案とする。

## 11. MVP画面構成の結論

MVPの主要画面は次の2つに限定する。

1. **ライブラリ画面**
   - 10,000件以上のアーカイブから探す
   - アーカイブ自体を管理する
2. **ビューア画面**
   - 1枚表示またはサムネイル一覧でアーカイブ内画像を見る
   - 単一または複数の不要画像を削除予約する

設定画面と操作履歴画面は将来実装とし、MVPでは安全側の固定動作を採用する。

## 12. 全画面に共通の規則（Ver.0.2.6）

全フェーズの完了後に行った画面の見た目の確認で、次のとおり確定した。

### 12.1 外観（テーマ）

- MVPでは、暗い配色（ダーク）に固定する。画像を見る時間が長く、明るい背景がまぶしくならないため
- ボタン・一覧・ツリーなどの標準の部品は、Windows 11 の見た目（Fluent）に合わせる
- アプリ独自の色（選択の強調、「削除予定」のラベル、画面全体を覆う表示）は、明るい配色でも暗い配色でも見分けられる色とする。選択や削除予定は、色だけでなく文字や印でも示す（3.5、4.6）
- ビューアの画像の背景は、配色によらず暗いままにする。ツールバーは、ほかの画面と同じくテーマに合わせる（Ver.0.2.9。ライトでも、画像を見る領域だけが暗い）
- ライブラリ画面では、一覧の領域（詳細表示・サムネイル表示）を、ウィンドウの地（左のツリー・ツールバー）より一段明るい面にし、角を丸めた細い枠で囲む。ツリー・ツールバー・一覧の境を、色の差と枠で示すため（Ver.0.2.7）。ウィンドウの地は半透明（Mica。壁紙の色がにじむ）のため、面は不透明な色にする。ビューア画面は、ツールバーと画像の領域の色がもともと違うため、変えない
- 将来、設定画面（SCR-03）で、ダーク / ライト / Windowsの設定に合わせる、を選べるようにする。そのとき画面の作りを変えずに済むよう、画面の色はテーマの色を参照する（開発環境設計書 5.3）

### 12.2 確認とお知らせのダイアログ

- 確認とお知らせは、Windowsの標準のメッセージボックスではなく、テーマに合わせたアプリのダイアログで表示する（標準のメッセージボックスは、暗い配色にならないため）
- 確認の選択肢は「（操作の名前）」/「キャンセル」とする（例: 「削除」「完全に削除」「外す」「統合して追加」）。「はい」/「いいえ」は使わない（何が起きるかをボタンの文字で示すため）
- 既定のボタン（Enter）はキャンセルで、Esc でもキャンセルになる。ダイアログを何も選ばずに閉じた場合もキャンセル（誤って破壊的な操作をしないため。DLG-01 と同じ）
- お知らせ（エラーの通知など）は「OK」だけで、Enter でも Esc でも閉じる
